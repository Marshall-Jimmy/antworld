## 1. 项目是什么、走到哪了

蚁群信息素（stigmergy）仿真：数千只蚂蚁靠轨迹信息素、路径积分与个体性格涌现觅食网络。
纯浏览器端（vanilla ES modules + WebGL2/Canvas2D + vite），无框架，唯一运行时依赖 tweakpane。

**最高准则（用户原话级）：行为要"有机真实"——程序化均匀观感=不合格；指标要诚实——
交付数字必须反映真实行程结构，发现旧数字掺假要大声作废（有先例，见 §5）。**

当前进度：P1.x（导航与真实感基础）→ P2.0（git 地基）→ P2.1（障碍绕行）→ P2.2（报警信息素+捕食者）→ P2.3（昼夜与天气）→ **P2.3.1（光污染治理，已完成）** → **P2.4（个体路线记忆，已完成）** → **P2.3.2（光污染 II：扩散长度压回触角尺度 + 自适应曝光，已完成）**。
已推 GitHub：https://github.com/Marshall-Jimmy/antworld（公开，origin/main 已跟踪，按阶段 tag）。
下一步（优先做，别急着开新功能）：**P2.3.2 留了一条未兑付的账**——出厂 dw=0.02 之后 `memFail`/`memShare`
这组双通道权重是在旧场尺度上标的，400 蚁小群体下记忆组吞吐只有基线 73.4%（⑤d FAIL，见 METRICS §6.11）。
之后再回到 P2.4b（场景预设 + 统计曲线 + 录像，原 ROADMAP 的 P2.4 内容顺延），或按 ANT_BIOLOGY §四 做 P2.5 能量与生死。

## 3. 代码地图

|---|---|---|
| core/config.js | 参数 schema（key/default/min/max/desc） | 一切新机制先在此注册参数，默认值=关。**两个出厂即开的例外**：`K_mem`=2（P2.4，真实性优先）、`autoPeak`=1（P2.3.2，因为 `effPeak=max(滑杆,自适应)` 结构上保证"没过曝的画面逐位不变"，它只可能在过曝处起作用）。`diffuseWeight` 出厂 0.06→**0.02** 是改旧参数的推导值，理由在 desc 里 |

| core/weather.js | **P2.3** 内源钟+温度窗口+风暴调度 → 一个复用 env 槽 | sim 层只读 env 不 import 本模块；风暴用独立随机流 seed+"\|wx" |

| sim/colony.js | SoA 状态容器 + 每步编排 | 经济事件（捕杀/卸货/弃货/重生）都在这；零分配热路径。**P2.4 记忆 = memA/memB 双缓冲 SoA**（32 航点/蚁，A 重放 B 记录），重放·记录·提交·废弃四件事都在 step() 里 |

| render/canvas2d.js | Canvas 兜底（PNG 管线另见 render_png.mjs） | 与 webgl 共用 palette.js；兜底画布必须是全新的一块（见 §5 教训15） |

## 4. 架构铁律（红线，违反=返工）

1. **bit 级回归**：改热路径（ant.js/colony.js/fields.js 算术）必须过 perf_check 校验和。
   现行基线见 §6；新基线必须 METRICS 记录在案。
2. **参数门控**：新机制一律 schema 参数默认 0/off = 旧行为 bit 级不变（P1.9 起每次验证过）。
3. **零分配热路径**：colony 每蚁每步复用 `_st`/`_out` 槽对象，不 new。
4. **每蚁 RNG 流**：门控关闭的代码块**不得消耗** uniform()/gauss()——否则下游随机序列全变，
   "旧行为 bit 级不变"即告破产。惊逃块、墙块都按此写（短路条件在最前）。
5. **数值红线**：校验和路径上不可用平方距离替换 Math.hypot；field 扩散核与 ant.js 的
   算术/表达式顺序冻结。
6. **诚实指标**：deliveries/吞吐必须与行程结构同读；跨机制变更后旧数字不可直比；
   假数字一经发现，在 METRICS 里正式作废并重定基（P2.2 作废了 P1.9/P2.1 全部旧基线）。
7. **交付节奏**：每阶段 commit + tag + git push（含 --tags）；commit message 附关键校验和与验收结论。

| P2.2 | 报警信息素 + 捕食者 + 诚实化 | 三课：①报警源只能是捕杀喷溅（惊逃也喷=恐慌云正反馈永不散）；②卸货必须纯物理判定（旧 \|h\|<巢盘 让 h≈0 壳蚁站食物上 60 次/秒永动卸货，旧基线全掺假）；③leak>0 时 h 返程中途必过零成极限环外壳（真实路径积分是累积误差非指数遗忘）→ leak 默认 0 |
| P2.3 | 内源钟昼夜 + 温度门控 + 雨前抢收 + 雨风冲刷 | 四课：①"到家"也必须纯物理判定——\|h\|<巢盘 会让参考点无界外漂成"假家"（同一把尺子实测 21.0% 的蚁把家认在野外，滞留被放大后就地在野地里"蛰巢"；MODE=phantom node weather_diag.mjs 可重跑）；②巢内滞留该按生物钟速率走表，不是卸货那一刻乘死常数；③昼夜响应必须超线性（dayCurve=3）——线性钟下活动相位占 85%，任何 Pearson 判据的天花板就是 −0.18；④饱和群体的"出巢率"榨不出 ×2，第二条腿是缩短行程（brisk 抑制触角扫描） |

| P2.3.1 | 有界对数色阶 + 三路径统一 + 蚂蚁改 alpha 混合 | 渲染层必须自证——**无 warn 不等于活着**：P2.3 的 6 处 `uniform vec3 uAmbient;;` 让 WebGL2 静默编译失败整整一个阶段，浏览器里跑的其实是 Canvas2D 兜底，而兜底又因画布已被占用必然黑屏。校验和 / weather_check / 验收 PNG 全都抓不到（PNG 管线绕开 DOM 与着色器）。根治=单一色阶来源 render/palette.js + HUD 自报后端；配套新门禁 glare_check（只量像素，25/25） |
| P2.4 | 个体路线记忆（32 航点/蚁 + 双通道份额制 + 扑空废弃） | 卖点被自己证伪：**"黎明火箭"不存在**。第一版单种子 1.39× PASS 是挑樱桃（三种子均值 0.995×）；第二版人工抹场读出 6720×/1.443× 是拿噪声当结论（在指数上升沿上取固定窗口比倍率）。真相：夜里走廊确实被蒸发（黎明场峰只有当日平台峰的 1/98~1/156），但群体约 27s 就从零踩回，真空期太短兑换不出吞吐。正常玩法下记忆**没有可宣称的吞吐红利**（总账 1.011×），可测表现是保真更高更稳、弃航更少、路线贴近几何下限；红利在**集体通道被持续摘走**时（⑤B 2.39×）和**捕食者撕碎走廊后的重建期**（走廊 73.7%→103.7%，三种子 3/3）。详见 METRICS 教训 ⑯–㉒ |
| P2.3.2 | 扩散长度压回触角尺度（`diffuseWeight` 0.06→0.02，推导值）+ 自适应曝光（`autoPeak`，色阶参考浓度跟蚁脚剂量走） | **超出感知距离的扩散 = 替蚂蚁回答它没问的问题**：dw=0.06 时信息素云的衰减长度 43.5 单位是触角（26 单位）的 1.67 倍，场里存着任何蚂蚁都读不到的信息，于是它们去追一团自己闻不见的云——把 dw 解到 ℓ≤触角，吞吐 **+7.1%**、失败行程 **−17.9%**，这是纯赚。第二条腿：光污染的主因**不在场层而在曝光锚点**（fog_before/after 肉眼几乎无差别就是证据），任何固定 peak 都只能在"常规玩法一片黑"和"富场糊成一坨"里选一边 ⇒ `effPeak=max(滑杆,蚁脚中位×0.5)`，只收光不加光。附带一课：**门禁工具自己也要被门禁**——本轮抓到 3 个量具自身的 bug（假场景、代码产生不了的配置、明细只印均值而判据吃最坏值），第三个让 ③a/③b 红得莫名其妙 |

## 6. 现行基线（2026-09-05，P2.3.2 出厂：`diffuseWeight=0.02` + `autoPeak=1` + `K_mem=2`）

- **校验和（perf_check，3600 步 / 5000 蚁 / seed=perfseed）**：ants `8288491.3883813173` /
  field `195.34836906715111` / deliveries `750` timeouts `69` 空手返巢 `1482`。
  基线重定链：2290（掺假）→731（物理卸货）→752（leak=0）→752+1552（物理返巢，P2.3 教训11）
  →8297548（P2.4 记忆出厂）→**8288491（本轮薄场出厂）**。
- **双基线钉（P2.3.2 新规矩：一条基线必须写清它钉在哪个 dw 上）**
  - `PARAMS=K_mem=0` ⇒ ants `8289087.5792887788` / field `195.34836906715111` / 750 / 69 / 1456
    ⇒ 关掉记忆必须逐位复现它，否则门控不成立。
  - `PARAMS=diffuseWeight=0.06` ⇒ ants `8297548.1091679782` / field `285.06957330616132` / 752 / 100 / 1552
    = **P2.4 的记录逐位复现**（含校验和末尾的有效数字）⇒ 本轮 sim 层只动了 `diffuseWeight` 一个自由度。
    这条证据比"同一版本跑两次对上"更强：它是一个**跨版本**的等式。P2.4 的旧 ants `8297548…` 从此降级为
    `dw=0.06` 的门控对照值（`8314152…`/`8296930…` 两代更早的号一并作废，只留在重定链里当脚注）。
  - memory_check ① 段同钉两组：**①b0** 把 dw 显式钉回 0.06 ⇒ 逐位复现 P2.3.1 旧码基线
    `8271063.288092 / 1791.475450` ✓；**①b1** 出厂 dw=0.02 ⇒ 复现本轮重录 `8363664.351491 / 1031.422461` ✓；
    **①c** 开记忆必须破恒等（差 −52625.862）✓，防止"两条基线都对上其实是假绿"。
- perf：K_mem=0 **2.604** → K_mem=2 **2.834 ms/step** @5000 蚁 ⇒ 记忆代价 **+8.8%**；

## 7. 已知差距与技术债

- ⭐**薄场下双通道权重失配（本轮唯一推不掉的真代价，优先级最高）**：`memFail`=0.6 / `memShare` 这一组混合权重
  **是在 dw=0.06 的场尺度上标定的**。把集体通道做窄做准之后，400 蚁小群体的**建成期**（集体通道还在时）
  记忆组吞吐 2604 vs 基线 3546 = **73.4%**（⑤d，判据线 95%；dw=0.06 同一格是 108.2% PASS）。
  ⇒ 私人路线相对权重过高、被劣质私人路线带偏。**本轮故意不动**：同一阶段再动一个自由度会毁掉全部归因。
  修法：以 dw=0.02 为条件重标 `memShare`/`memFail`（扫描 + 分位判据），跑 `SUB=weak node memory_check.mjs` 当回归网。
- **③a 的绝对量纲阈值不可跨 dw 复用**：`逐种子最大黎明场峰 < 10` 这个"10"是 P2.4 在 dw=0.06 的场上顺手写的，
  薄场把场峰整体抬高之后它必然红（出厂读数最大 23.1）。**改成比值或分位**才是尺度不变的判据。FAIL 保留、阈值未改。
- **捕食者「吞吐回升 ≥ 25%A」判据跨种子脆弱**：本轮三种子 × 两 dw 矩阵跑下来，两栏都是 2 胜 1 负、
  FAIL 落在不同种子（0.06=12% / 0.02=19%），中位回升 46% vs 57%。⇒ P2.4 记的"8/8"是抽签，
  其三种子表本来就是 2 胜 1 平。**作废**"腿 A 造成 52%→19% 退化"这条归因（METRICS §6.7）。
  修法：扩到 5–8 种子，或改成"回升的分位数"判据。
- **报警红仍然是固定峰值**：`alarmPeak`=1.2 只管色阶，捕杀高峰期场值能堆到 64（约 5.7 个倍频程）——
  同一类毛病的另一处。下一轮把 P2.3.2 这套（锚点=脚下载量 + 只收光不加光 + 门控回滑杆）原法搬给报警通道。

- **记忆没有"正常玩法吞吐红利"**（P2.4 实测，不是缺陷而是结论）：昼夜三天总账仅 **1.011×**，因为夜里
  走廊确实被蒸发（黎明峰 32~156×，按三种子汇总最小仍有 98×；判据是比值不是绝对值），但群体
  **约 27s** 就从零踩回，真空期太短兑换不出卸货量。别把这条当"还没做好"，
  它已经被三种子否证过两次（METRICS 教训 ⑱⑳㉑）。
  **P2.3.2 更新**：dw 降到出厂值 0.02 之后，同一个 ③ 段读出总账 **1.285×**（逐种子 1.504/0.991/1.510×，
  基线自身跨种子极差从 1.2% 涨到 **43.7%**）——数字涨了，但按同一条纪律**仍然不予宣称红利**；
  而且这一段同时把 ③a/③b 两条前提判据顶红（METRICS §6.9/§6.10）。dw=0.06 的对照组读数见 METRICS §6.12。
- **记忆红利的真实兑现处已量化，但强度有限**：①集体通道被持续摘走时 ⑤B **2.39×**（基线保真 3.0% vs 记忆保真 60.5%）；②捕食者撕碎走廊后的**重建期**——三种子走廊重建 73.7%→**103.7%**（3/3 单调，可作结论），
  吞吐回升 34.0%→49.7%（2 胜 1 平，只能说"通常更好"不能说"总是更好"）。这两条是目前唯一站得住的正结果。
- **两个记忆参数未经独立标定**（是"能用"不是"最优"）：`memFail`=0.6 的扑空归因门槛与 `memForget`=2 的遗忘节拍只过了 ①②④⑤
  的合理性检验（④ 撤源后覆盖 100%→75%→**28%**，判据要求 ≤50%，余量足），**没做过扫描寻优**。
  另外 ⑤ 的"建成期也 +8.2%"是**单种子**观察，够不上结论。想动这几个数先跑 `node memory_check.mjs` 当回归网。
- **信息素衰减偏快**：trail 半衰期 ~23s，真实跨度 1 min–数天（建模惯例 ~5 min）；alarm 13.5s
  对应真实的秒–分钟量级，尚可。整体再校准前先想清楚破坏哪些既有标定。
- **K_wall=4 vs 0**：三种子方向支持避让但方差大（有墙 56~128，跨种子极差 130%），仍**不能**下统计结论。
  P2.4 的三种子复测把它从"1 种子的 111→179"降级为"不稳健"，见 METRICS 墙场景否证表。
- **即时重生=新蚁**是简化（真实卵→工 ~43 天），归 P2.5 数量动态。
- **报警渲染峰值钳制**：alarmPeak=1.2 只管色阶，高捕杀期场值可堆到 64——渲染正常，别误判成 bug。
  同理信息素场在 P2.3 的长程管饱场景可达 58。P2.3.1 之后这不再是问题：色阶改成有界对数上肩，
  `peak` 是**半亮点**而不是「最亮」，256×peak 才到白热上限，任何浓度都不会再截断成白（溢出恒为 0）。
- **一夜蒸发（P2.4 已量化并部分兑付）**：dayLength=240 时正午场峰 58.3 → 深夜 6.0（半衰期 23s vs 夜长
  ~120s），网络每夜清空、白天重新成路。K_mem=2 后"重建"从几十秒变为"到岗即有路线"，但**兑换成的吞吐
  只有 **1.011×**（dw=0.06 时代；出厂 dw=0.02 下同段 1.285×，但极差 43.7%，见 METRICS §6.12 与上面第一条）；真正吃到红利的是集体通道被持续摘走的场景（⑤B 2.39×）与捕食者重建期。
- **抢收没有"巢内预备队"**：真实 ×2–3 是从巢内任务池抽人，本模型全群皆外勤（常态 90% 已在
  巢外），出巢倍率天花板只有 ~1.6×。等 P2.5 年龄多态/任务分配补上这一维。
- **ROADMAP.md 的 P2.2 节已过时**（写的是"惊逃蚂蚁也沉积"，实际为防正反馈改为死者喷溅）；
  机制以 METRICS.md 为权威，ROADMAP 只看后续阶段。
- 报警剂量只有 panic 分支；真实的低浓度=聚集查看（剂量分级）未做（ANT_BIOLOGY §五，增强方向）。
